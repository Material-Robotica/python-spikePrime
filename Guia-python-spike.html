Guía de Programación en Python para LEGO SPIKE Prime

Manual Didáctico · Nivel Básico y Nivel Avanzado

Plataforma: SPIKE Prime / Pybricks Entorno: code.pybricks.com Lenguaje: Python (MicroPython)
Nivel básico

Primeros programas: mover el robot, girar, usar luces y sonido, y leer sensores con decisiones simples.

1. Introducción y Configuración del Entorno

En esta guía el robot se programa directamente en Python con Pybricks, el mismo firmware que usa Open Roberta para el SPIKE Prime. El código se escribe en Pybricks Code, un editor que funciona en el navegador, y se envía al hub por Bluetooth. No hace falta instalar nada en la computadora. Es el paso siguiente después de los bloques de Open Roberta: las mismas ideas, escritas como programa textual.

A. Antes de empezar

  • El hub debe tener instalado el firmware Pybricks (ver la guía Open Roberta + SPIKE Prime, Parte A).
  • Usar una computadora con Bluetooth (las Ceibalitas con Windows 11 lo tienen) y el navegador Google Chrome o Microsoft Edge.
  • Activar el Bluetooth de Windows, pero no emparejar el hub desde la configuración de Windows: la conexión la hace el navegador.
  • Cerrar cualquier pestaña del Open Roberta Lab: el hub acepta una sola conexión a la vez.

B. Ciclo de trabajo

  1. Abrir code.pybricks.com y crear un archivo nuevo (ícono +), de tipo Python, con un nombre sin espacios (por ejemplo mover.py).
  2. Encender el hub con el botón central.
  3. Tocar el botón de Bluetooth de Pybricks, elegir el hub en la ventana del navegador y tocar Emparejar.
  4. Escribir el programa y tocar ▶: el programa se envía al hub y se ejecuta.
  5. Para detenerlo: botón ■ de Pybricks o botón central del hub.
La consola: debajo del editor aparece todo lo que el programa imprime con print() y también los mensajes de error, con el número de línea donde ocurrieron.
Consejo pedagógico: conviene resolver primero el problema con bloques en Open Roberta Lab y luego reescribirlo en Python. La tabla de equivalencias de la sección 2 ayuda a hacer esa traducción.

2. Estructura Base de un Programa Python

Todos los programas comienzan con la misma plantilla: se importan las clases, se definen las constantes del robot y se crean el hub, los motores y la base móvil (DriveBase, el objeto que mueve el robot). Los ejemplos de esta guía se escriben debajo de esta plantilla.

from pybricks.hubs import PrimeHub
from pybricks.pupdevices import Motor, ColorSensor, UltrasonicSensor, ForceSensor
from pybricks.parameters import Button, Color, Direction, Port, Icon
from pybricks.robotics import DriveBase
from pybricks.tools import wait
 
# --- Configuración del robot (ajustar según el modelo) ---
PUERTO_MOTOR_IZQ = Port.A
PUERTO_MOTOR_DER = Port.B
DIAMETRO_RUEDA_MM = 56
DISTANCIA_ENTRE_RUEDAS_MM = 112
 
hub = PrimeHub()
motor_izq = Motor(PUERTO_MOTOR_IZQ, Direction.COUNTERCLOCKWISE)
motor_der = Motor(PUERTO_MOTOR_DER)
robot = DriveBase(motor_izq, motor_der, DIAMETRO_RUEDA_MM, DISTANCIA_ENTRE_RUEDAS_MM)
 
# --- Programa del estudiante (a partir de aquí) ---
hub.speaker.beep()
Concepto clave: el objeto robot (DriveBase) recibe distancias en milímetros y ángulos en grados, y calcula cuánto debe girar cada motor. Para eso necesita conocer el diámetro de las ruedas y la distancia entre ellas.
Python y la sangría: los espacios al inicio de cada línea son parte del lenguaje. Indican qué instrucciones están dentro de un while, for, if o def. Además, mayúsculas y minúsculas importan: PrimeHub no es lo mismo que primehub.

3. Luces, Sonido y Pantalla

El hub tiene una matriz de luces de 5×5, una luz de color en el botón central, un parlante y botones. Son la forma más rápida de comprobar que un programa funciona, aun sin motores conectados.

Ejemplo 1: Saludo del Robot

hub.light.on(Color.GREEN)        # luz del botón central en verde
hub.display.icon(Icon.HAPPY)     # cara sonriente en la matriz
hub.speaker.beep(440, 300)       # nota La durante 300 ms
wait(1000)
hub.display.text("Hola")         # texto que se desplaza
hub.display.number(42)           # número de -99 a 99
wait(2000)

Al terminar el programa, el hub borra la matriz de luces. Por eso el wait() final es necesario para alcanzar a ver el número.

Ejemplo 2: Esperar un Botón

hub.display.icon(Icon.ARROW_LEFT)
 
while Button.LEFT not in hub.buttons.pressed():
    wait(10)
 
hub.speaker.beep()
hub.display.text("Listo")

El programa queda detenido en el while hasta que se aprieta el botón izquierdo del hub.

Iconos disponibles: además de Icon.HAPPY y Icon.HEART existen, entre otros, Icon.SAD, Icon.ARROW_UP e Icon.ARROW_RIGHT.

4. Movimiento Básico: Adelante y Atrás

La velocidad de la base móvil se configura con robot.settings(), en milímetros por segundo. Un valor entre $100$ y $250$ mm/s es adecuado para el aula.

Ejemplo 1: Avanzar y Retroceder por Distancia Determinada

velocidad = 150      # mm/s
distancia_mm = 300   # 30 cm
 
robot.settings(straight_speed=velocidad)
 
robot.straight(distancia_mm)     # avanza
wait(500)
robot.straight(-distancia_mm)    # retrocede

straight() espera a que el robot termine de recorrer la distancia antes de pasar a la línea siguiente.

Ejemplo 2: Control Continuo por Tiempo

robot.drive(180, 0)   # avanza a 180 mm/s, sin girar
wait(2000)            # durante 2 segundos
robot.stop()

drive() no espera: el robot arranca y el programa continúa de inmediato. Por eso es necesaria la pausa antes de stop().

5. Maniobras y Giros

En robótica móvil diferencial existen dos modalidades principales de giro:

  1. Giro Sobre su Eje (Pivot): las ruedas giran en sentidos opuestos. En Pybricks: robot.turn(grados).
  2. Giro Curvo: ambas ruedas avanzan a velocidades diferentes. En Pybricks: robot.curve(radio_mm, grados).

En Pybricks los ángulos positivos giran a la derecha (sentido horario) y los negativos a la izquierda.

Diferencia con leJOS (EV3 en Java): en leJOS el ángulo positivo gira a la izquierda. Al pasar un programa de un robot al otro, revisar el signo de los giros.

Ejemplo 1: Giro por Ángulo Determinado

robot.settings(turn_rate=90)   # 90 grados por segundo
 
robot.turn(90)    # derecha
wait(500)
robot.turn(-90)   # izquierda
Calibración: si el robot gira más o menos de 90°, ajustar la constante DISTANCIA_ENTRE_RUEDAS_MM. Si gira de menos, aumentarla; si gira de más, disminuirla. Para distancias incorrectas, revisar DIAMETRO_RUEDA_MM.

Ejemplo 2: Recorrido Cuadrado usando un Bucle for

LADO_MM = 300
 
robot.settings(straight_speed=150, turn_rate=60)
 
for i in range(4):
    robot.straight(LADO_MM)
    robot.turn(90)

Ejemplo 3: Giro Curvo

robot.settings(straight_speed=120)
 
robot.curve(200, 90)   # cuarto de circunferencia de 20 cm de radio

Probar cambiando el signo del radio y del ángulo para descubrir hacia dónde gira el robot en cada caso.

Para giros más precisos con el giroscopio del hub, ver la sección 10 (nivel avanzado).

6. Uso de Sensores

En Pybricks cada sensor es un objeto. Se crea indicando el puerto y se lee llamando a uno de sus métodos. No hace falta cerrarlo al terminar.

Sensor Puerto Típico Clase en Pybricks Método y valor
Fuerza / Pulsador Port.E ForceSensor pressed() → True / False
force() → newtons
Color / Luz Port.C ColorSensor reflection() → luz reflejada de 0 a 100
color() → Color.RED, Color.BLACK…
Ultrasonido Port.D UltrasonicSensor distance() → milímetros
Giroscopio (interno) en el hub hub.imu heading() → grados girados

A. Sensor de Fuerza (Detección de Colisión)

pulsador = ForceSensor(Port.E)
 
robot.drive(100, 0)
 
while not pulsador.pressed():
    wait(10)   # pausa para no saturar el hub
 
robot.stop()
robot.straight(-150)   # retrocede 15 cm

B. Sensor de Ultrasonido (Evasión de Obstáculos)

UMBRAL_MM = 200
ultrasonido = UltrasonicSensor(Port.D)
 
robot.drive(150, 0)
 
while True:
    distancia = ultrasonido.distance()
 
    if distancia < UMBRAL_MM:
        # Esquivar obstáculo
        robot.stop()
        robot.turn(90)
        robot.drive(150, 0)
 
    wait(50)

El ultrasonido ya entrega milímetros, sin necesidad de conversión. El bucle se detiene con el botón central del hub.

7. Retos Básicos

Desafíos cortos para practicar lo visto en el nivel básico. Cada uno se resuelve con pocas líneas.

Reto 1: Semáforo

La luz del botón central pasa por verde, amarillo y rojo, con tiempos distintos para cada color, y se repite cinco veces.

Pistas: Color.YELLOW, wait() y for i in range(5):.

Reto 2: Figuras Geométricas

A partir del ejemplo del cuadrado, hacer que el robot recorra un triángulo equilátero y luego un hexágono.

Pistas: el ángulo de giro es $360 / \text{cantidad de lados}$.

Reto 3: Alarma de Proximidad

El robot está quieto. Si algo se acerca a menos de $15\text{ cm}$, la luz se pone roja y suena un pitido; si no, la luz queda verde.

Pistas: while True:, if / else y distance().

Reto 4: Carrera hasta la Pared

El robot espera a que se presione el sensor de fuerza, avanza hasta quedar a $10\text{ cm}$ de una pared, se detiene y muestra una cara sonriente.

Pistas: combinar los ejemplos A y B de la sección 6.

8. Funciones

Una función agrupa con def un conjunto de instrucciones bajo un nombre. Permite reutilizar maniobras y hace que el programa principal se lea como una lista de pasos.

Ejemplo 1: Función sin Parámetros

def esquivar():
    robot.stop()
    hub.speaker.beep()
    robot.straight(-100)
    robot.turn(90)
 
esquivar()

Ejemplo 2: Función con Parámetros

def poligono(lados, largo_mm):
    angulo = 360 / lados
    for i in range(lados):
        robot.straight(largo_mm)
        robot.turn(angulo)
 
poligono(3, 300)   # triángulo
poligono(6, 150)   # hexágono

Ejemplo 3: Función que Devuelve un Valor

UMBRAL_MM = 200
ultrasonido = UltrasonicSensor(Port.D)
 
def hay_obstaculo():
    return ultrasonido.distance() < UMBRAL_MM
 
robot.drive(150, 0)
 
while True:
    if hay_obstaculo():
        esquivar()
        robot.drive(150, 0)
    wait(50)
Concepto clave: las funciones deben definirse antes de usarse. En el ejemplo 3, la función esquivar() del ejemplo 1 también debe estar escrita más arriba en el programa.

9. Seguidor de Línea

Control Proporcional

Para seguir el borde de una línea negra con suavidad, se calcula el error con respecto al punto medio de luz reflejada $T = \frac{C_{\text{blanco}} + C_{\text{negro}}}{2}$. La corrección es proporcional al error y se usa como velocidad de giro de drive(): 

BLANCO = 85
NEGRO = 10
PUNTO_MEDIO = (BLANCO + NEGRO) / 2
KP = 1.2
VELOCIDAD = 100   # mm/s
 
sensor_color = ColorSensor(Port.C)
 
while True:
    error = sensor_color.reflection() - PUNTO_MEDIO
    correccion = KP * error
    robot.drive(VELOCIDAD, correccion)
    wait(10)
Ajustes: medir la luz sobre el blanco y sobre el negro (ver sección 12) para obtener BLANCO y NEGRO. Si el robot se aleja de la línea en lugar de seguirla, cambiar el signo de KP. Si oscila mucho, bajar KP o la velocidad.

10. Giroscopio

El hub tiene un giroscopio interno (hub.imu) que mide cuántos grados giró el robot. No ocupa ningún puerto.

Ejemplo 1: Giros Corregidos con el Giroscopio

robot.use_gyro(True)   # rectas y giros corregidos con el giroscopio
 
for i in range(4):
    robot.straight(300)
    robot.turn(90)

Comparar este cuadrado con el de la sección 5: con el giroscopio activado el robot debería volver más cerca del punto de partida. use_gyro() está disponible en las versiones recientes de Pybricks.

Ejemplo 2: Medir un Giro Hecho a Mano

hub.imu.reset_heading(0)
 
while abs(hub.imu.heading()) < 90:
    print("Rumbo:", hub.imu.heading())
    wait(100)
 
hub.speaker.beep()
hub.display.icon(Icon.HAPPY)
wait(1000)

Girar el robot con la mano sobre la mesa: cuando llega a 90° hacia cualquier lado, suena el pitido. abs() devuelve el valor absoluto, por eso funciona en ambos sentidos.

Hub quieto al arrancar: el giroscopio se calibra solo cuando el hub está inmóvil. Dejar el robot quieto un par de segundos después de encenderlo y antes de ejecutar el programa.

11. Proyectos Integradores

Propuestas integradoras para trabajar algoritmos, condicionales, bucles y funciones:

Proyecto 1: Explorador Autónomo

El robot avanza en un área delimitada. Si detecta un obstáculo a menos de $20\text{ cm}$ con el ultrasonido, emite una alerta, retrocede y elige al azar girar a la izquierda o a la derecha.

Pistas: hub.speaker.beep() para la alerta; from urandom import choice y choice([-90, 90]) para elegir el lado.

Proyecto 2: Repartidor de Logística

Sigue una línea negra continua. Cuando el sensor detecta una marca de color rojo, se detiene durante 3 segundos para simular la descarga de mercancía y reanuda la ruta.

Pistas: método color() y comparación con Color.RED.

Proyecto 3: Resolutor de Laberintos

Implementar el algoritmo de la mano derecha utilizando el sensor de ultrasonido en un lateral para mantener una distancia fija respecto a la pared mediante la fórmula de error $e = d_{\text{deseada}} - d_{\text{medida}}$.

Pistas: aplicar la misma idea del seguidor de línea, usando la distancia en lugar de la luz.

12. Buenas Prácticas de Programación en Robótica

  • Nombres significativos y constantes: declarar puertos y parámetros en mayúsculas al inicio del programa para facilitar modificaciones en el aula. 
    PUERTO_ULTRASONIDO = Port.D
DISTANCIA_UMBRAL_MM = 200
  • Funciones para las maniobras: agrupar con def las acciones que se repiten (ver sección 8).
  • Pausas en bucles continuos: incluir siempre una pequeña pausa (por ejemplo wait(10)) dentro de los bucles para no saturar el hub.
  • Salida de depuración: mostrar los valores de los sensores en la consola para calibrar umbrales: 
    while True:
    print("Luz:", sensor_color.reflection())
    wait(200)
  • Ejecutar sin la computadora: el hub guarda el último programa enviado. Desconectar el Bluetooth en Pybricks y apretar el botón central para ejecutarlo de nuevo.
  • Guardar los archivos: Pybricks Code guarda los programas en el navegador de esa computadora. Para conservarlos, descargarlos desde su explorador de archivos y guardarlos en una carpeta propia o en Drive.
  • Batería: con la batería baja los motores pierden fuerza y los giros se vuelven imprecisos. El voltaje se consulta con print(hub.battery.voltage()) (en milivoltios).

13. Problemas Frecuentes

Mensaje / síntomaSolución
El hub no aparece en la ventana de BluetoothVerificar que esté encendido y que no esté conectado al Open Roberta Lab en otra pestaña. Si sigue sin aparecer, apagarlo y encenderlo.
IndentationError / SyntaxErrorRevisar la línea indicada: sangría desalineada, falta de : al final de if, while, for o def, o paréntesis sin cerrar.
NameErrorSe usa algo que no está importado o un nombre mal escrito. Revisar las líneas from … import … y las mayúsculas.
OSError: [Errno 19] ENODEVNo hay ningún motor o sensor en el puerto indicado. Revisar el cable o cambiar el Port.
El robot va al revés o gira en círculosCambiar cuál motor lleva Direction.COUNTERCLOCKWISE, o revisar que los puertos izquierdo y derecho no estén invertidos.
La distancia o el giro no coinciden con lo pedidoMedir el robot y corregir DIAMETRO_RUEDA_MM y DISTANCIA_ENTRE_RUEDAS_MM (sección 5).
